# Modelo de Receita - Consumo da Plataforma (2026-11-09)

## Contexto
Como cobrar pelo consumo de APIs e do Estúdio de Aplicações. Fonte: notas do tl;dv.

## Pontos discutidos
- Proposta inicial: planos por cotas de consumo (hits mensais e simultâneos). Porte do município pode não refletir o consumo real; tráfego e payload pesam no custo.
- Plano Starter só de consulta; escrita cobrada à parte; domínios de negócio com valor diferente (ex.: emissão de guias tributárias).
- Concorrentes não cobram por consumo nem acesso a APIs (espaço para diferenciação). Editais exigem API, mas não definem cobrança.
- Estúdio como gateway de governança das APIs de fornecedores e parceiros do município; oferta conjunta Estúdio + APIs em avaliação no Comercial.
- Integração com o Banco do Brasil é demandada, mas não rentabilizada; automações (extrato, DVP) oferecidas sem custo.
- Data lake já apresentado ao CEO, com cronograma. Um parceiro já publicou sua API no Estúdio.

## Decisões
- Nenhuma registrada.
